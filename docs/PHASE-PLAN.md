# PHASE-PLAN — wp-cleanup.php レビュー指摘の修正

## 背景
レビューにより、確認画面の表示と実際の削除挙動が食い違う「データ消失リスク」が2件見つかった。
表示が「安全」と示す一方で実際は削除する（またはその逆）という、このツールで最も避けたいズレ。
併せてセキュリティ・安全性の改善を行う。

## 修正方針・手順

### 1. プレフィックス前方一致で別インストールを巻き込む（要修正）
- 症状: 対象プレフィックス `wp_` の `LIKE 'wp\_%'` が別インストール `wp_old_` のテーブルも拾う。
  一方で確認画面は `wp_old_` を「削除されません」と誤表示していた。
- 対策: `separateForeignTables()` を追加。検出済みプレフィックスのうち
  「対象プレフィックスで始まる」かつ「マルチサイトのサブサイト表記 `^prefix\d+_$` ではない」ものを
  別インストールとみなし、そのテーブルを削除対象から除外・保護する。
  - マルチサイトのサブサイト（`wp_2_` 等）は対象インストールの一部なので削除対象に残す。
  - トレードオフ: `wp_myplugin_options` のように偶然コア名で終わるプラグインテーブルも
    保護側に倒れて残る場合がある（＝削除漏れ）。破滅的な他サイト削除を防ぐため安全側を優先し、
    保護したテーブルは画面に明示して手動削除を促す。
- 確認画面の「削除されない他プレフィックス」表示も、マルチサイトサブサイトを除外して正確化。

### 2. 入れ子WordPressの警告が実態と逆（要修正）
- 症状: ホワイトリスト外ディレクトリの入れ子WPは実際には削除されないのに「削除対象」と表示。
- 対策: `classifyNestedWP()` で各入れ子を「wp-content等の配下＝削除される」／
  「それ以外＝保護される」に分類し、2種類のカードで正確に表示。

### 3. ドキュメントルート直下の `.htaccess` 等を無条件削除（改善）
- 対策: `wpKnownFilesFor()` を追加。ドキュメントルート直下では
  `.htaccess` / `.htpasswd` / `.user.ini` を削除対象から除外（WP以外のルール保護）。
  確認画面の表示と実削除の両方に反映。

### 4. DB認証情報をセッションに平文保存（改善）
- 対策: `$_SESSION['wp_cleanup_config']`（DB_PASSWORD含む）の保存を廃止。
  実行時に `wp-config.php` を再解析して接続情報を得る。

### 5. `EXPIRES_AT = 0`（無制限）の注意喚起（改善）
- 対策: 無制限設定時はログイン画面で警告表示。

## 確認項目
- `php -l` で構文エラーなし。
- 通常サイト（単一プレフィックス）で対象テーブルが正しく列挙される。
- マルチサイト（`wp_2_` 等）のサブサイトテーブルが削除対象に**残る**。
- 別インストール（`wp_old_` 等）のテーブルが削除対象から**除外・保護**表示される。
- 入れ子WPが配置場所に応じて正しく「削除／保護」表示される。
